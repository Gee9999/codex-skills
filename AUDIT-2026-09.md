# GitHub candidate audit for Proto

Date: 2026-09-16

## Decision

Add a narrow Proto integration skill for codebase-memory-mcp, but do not bundle or silently install its native binary. It is the strongest fit for Proto's current needs: understanding a Vite storefront/admin codebase, tracing API routes, and investigating catalogue/stock failures. Its releases publish checksums, attestations, and security verification, but the tool reads repositories, writes agent configuration, and spawns processes, so installation remains explicit and must be audited on each machine.

## Candidates

### 1. codebase-memory-mcp — add as an optional integration

Fit: High. Its local code graph can map functions, routes, call chains, cross-service links, dead code, and impact analysis.

Risk: Medium. The installer writes agent configuration and the process has broad local filesystem access by design. The project documents path containment, local-only indexing, checksums, Sigstore/SLSA evidence, and release scanning. Pin and verify a release before use.

Action: Added proto-codebase-intelligence; optional tool installation is documented, not automated.

Source: https://github.com/DeusData/codebase-memory-mcp

### 2. ui-ux-pro-max-skill — defer

Fit: Medium-high for storefront design and accessibility. It supports React, Tailwind, shadcn/ui, and Codex, and is MIT licensed.

Risk: Not acceptable for automatic inclusion yet. GitHub's advisory database reports CVE-2026-7596 affecting the slide generator in versions up to 2.5.0, with unknown patched status. It also overlaps with the existing Product Design skills.

Action: Do not add until the affected component and patched version are independently verified.

Source: https://github.com/nextlevelbuilder/ui-ux-pro-max-skill

### 3. Teley — keep as a separate diagnostic app

Fit: Medium for reproducing API latency and trace behaviour. It can view OpenTelemetry and Sentry traces locally and can be self-hosted.

Risk: It is an observability application, not a Codex skill. The hosted mode relays telemetry through a room; self-hosting adds operational work.

Action: Use only for a specific debugging session; do not add to the skills bundle.

Source: https://github.com/logaretm/teley

### 4. Paperclip — defer

Fit: Low-medium. It coordinates multiple coding agents and has audit/secret-management features.

Risk: It introduces a substantial agent-orchestration platform and operational surface that Proto does not currently need.

Action: Revisit only if Proto work becomes a multi-agent project with persistent job management.

Source: https://github.com/paperclipai/paperclip

### 5. falcolee/e-commerce-dashboard — reference only

Fit: Medium as UI inspiration for catalogue, orders, customers, analytics, RBAC, and mock APIs.

Risk: It is a standalone dashboard template, not a drop-in Proto dependency. Importing it would create UI and architectural duplication.

Action: Study patterns selectively; do not install or vendor.

Source: https://github.com/falcolee/e-commerce-dashboard

### 6. Vendure / Spree Commerce — architecture references only

Fit: Potentially high only if Proto decides to replace or substantially replatform its commerce backend.

Risk: Both imply a major commerce architecture decision. Vendure's current major line has had serious security patch releases and its v3 core is GPLv3, so licensing and migration impact require a dedicated decision.

Action: Do not add or adopt. Use for comparison if a future replatforming proposal is created.

Sources:
- https://github.com/vendurehq/vendure
- https://github.com/nom4dlive/spree-commerce
